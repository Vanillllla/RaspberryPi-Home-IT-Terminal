# Дорожная карта RaspberryPi-Home-IT-Terminal

Предлагаемый порядок работ следует [концепции проекта](PROJECT_VISION.md). Объём каждой последующей итерации согласуется отдельно.

## Выполненные итерации

По уточнённому заданию этапа 1 реализованы запуск в WSL, рабочие столы, сохранение ячеек в SQLite, обнаружение плагинов, Clock и контракт Widget/Details/Settings с необязательным Python backend. Ниже сохранён исходный порядок развития проекта. При выборе следующего этапа учитывайте уже реализованную часть пунктов 1–5. Инструкции и сценарий проверки находятся в [README](../../README.md).

В этапе 2 реализованы перелистывание рабочих столов пальцем и мышью, переходы кнопками и клавиатурой, отменяемое удержание ручки и выбор свободной ячейки. Позиция хранится в прежнем поле `slot`. Размеры виджетов, дублирование и редактирование оформления остаются для последующих итераций.

В этапе 3 контракт v1 применён ко второму плагину с Widget, Settings и Details. Меню ⋯ управляет экземпляром, включая удаление и освобождение ячейки. Следующие изменения сетки и оформления выбираются отдельной итерацией.

В следующей итерации реализованы квадратная сетка, размеры экземпляров и свободный перенос с привязкой при отпускании.

Первая версия визуального конструктора сохраняет общие шаблоны в SQLite. Доступны пять элементов, связи по таймеру и внутренней команде, три готовых действия и вычисления Python в отдельном процессе.

Сохранённое состояние синхронизируется между браузерами через уведомления FastAPI WebSocket и снимки REST. Браузеры сохраняют локальную навигацию и черновики и переподключаются автоматически.

## 0. Зафиксировать требования

**Готовность.** В репозитории есть полная концепция, постоянные инструкции для Codex и план этапов с проверяемыми результатами.

## 1. Запустить пустое ядро в WSL

Поднять FastAPI и оболочку рабочего стола на React/TypeScript. Ввести централизованные дизайн-токены для адаптивного интерфейса. Описать команды локального запуска.

**Проверка.** В Debian под WSL проект запускается без Docker при пустом каталоге плагинов. В браузере Windows открывается пустой рабочий стол и проходит запрос к REST API.

## 2. Сохранить состояние рабочего стола

Определить модель SQLite и REST API для одного профиля, его рабочих столов и экземпляров. Хранить ссылку на идентификатор плагина независимо от его наличия на диске. Для каждого WidgetInstance сохранять идентификатор, стол, позицию, размеры, функциональные настройки и оформление.

**Проверка.** Создать через API два экземпляра одного плагина на разных столах. Изменить настройки и положение одного, перезапустить сервер и прочитать оба. Изменения сохранились только у выбранного экземпляра.

## 3. Подключить первый независимый плагин

Описать контракт manifest и точек входа Widget, Details, Settings и необязательного Python backend, а также порядок подключения ресурсов и зависимостей. Реализовать обнаружение папок в `plugins/`. На примере часов с датой проверить путь от добавления папки до отображения виджета. На этом этапе допустимы пересборка frontend и перезапуск backend.

**Проверка.** Часы подключаются без ручной правки ядра. После удаления папки на месте экземпляров появляются заглушки, после возврата плагина восстанавливаются часы с прежними настройками. Ошибка загрузки или отображения тестового плагина оставляет часы и рабочие столы доступными.

## 4. Реализовать навигацию и редактирование сетки

Добавить независимые страницы, горизонтальные свайпы, переключение мышью и сочетания Ctrl + Left / Ctrl + Right. Обеспечить добавление и удаление экземпляра, перенос после длительного удержания и изменение размера.

**Проверка.** Разместить два виджета, переместить один и изменить его размер. После обновления страницы раскладка сохраняется. Повторить базовые действия касанием и мышью. Колесо мыши сохраняет текущий стол.

## 5. Проверить представления виджета и завершить MVP

Подключить к оболочке необязательные Details и Settings. Проверить настройки отдельного экземпляра и их независимость от оформления. Сверить адаптивные карточки с горизонтальным форматом 7–10 дюймов.

**Проверка.** Открыть Details почти на весь экран и вернуться кнопкой закрытия на тот же стол. Изменить настройки только одного экземпляра. Нажатие кнопки внутри виджета выполняет её действие без начала переноса или смены стола. Повторить проверку для плагина только с Widget. Проверить доступ из доверенной локальной сети в границах раздела 9 концепции.

## 6. Развернуть терминал на Raspberry Pi 5

Перенести проверенную версию на Raspberry Pi 5 с 8 ГБ RAM. Настроить локальный запуск через systemd и Chromium Kiosk Mode. Проверить раскладку и жесты на физическом горизонтальном экране.

**Проверка.** После перезагрузки устройства терминал самостоятельно открывает сохранённый рабочий стол. Интерфейс доступен со второго устройства по LAN и через настроенную доверенную VPN.

## 7. Развивать интеграции по одной

Выбирать отдельным этапом проверку доступности Hysteria 2, мониторинг Proxmox и ресурсов, Home Assistant, мониторинг локальной сети или пользовательскую HTTP/API-интеграцию. Применять WebSocket при необходимости оперативных обновлений. Секреты обрабатывать на сервере.

**Проверка каждой интеграции.** Подключить плагин по опубликованному в репозитории контракту. Проверить штатные данные и недоступность источника. Остальные виджеты продолжают работать.

## Долгосрочные направления

Порядок этих итераций определяется после проверки ядра на реальных сценариях.

- Добавить серверные профили с ручным переключением и автоматическим выбором по размеру или классу устройства. Проверить восстановление столов и настроек каждого профиля.
- Расширить оформление темами, обоями и настройками отдельных экземпляров. Проверить сохранность функциональных настроек при смене темы.
- Развить модель безопасности и поставки плагинов. Согласовать авторизацию, права, разрешения, управление зависимостями и раздельное исполнение сложных плагинов перед динамической установкой ZIP-пакетов и созданием публичной библиотеки.
- Добавить визуальный конструктор и редактор Python-обработчиков. Проверить, что созданный виджет подключается через общий контракт плагинов.
