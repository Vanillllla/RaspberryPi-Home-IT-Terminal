# Контракт плагинов v1

Сервер при старте ищет `plugins/*/manifest.json`. Vite обнаруживает модули `plugins/*/index.tsx` и загружает компонент при первом отображении. Идентификатор совпадает с именем папки и остаётся постоянным между версиями. На него ссылаются сохранённые экземпляры.

## Минимальный пример

Создайте папку `plugins/greeting/` с двумя файлами. В `manifest.json` укажите:

```json
{
  "apiVersion": 1,
  "id": "greeting",
  "name": "Приветствие",
  "version": "1.0.0",
  "description": "Короткая надпись для рабочего стола",
  "capabilities": []
}
```

Допустимы строчные латинские буквы, цифры и дефис. Первый символ идентификатора — буква. Экспортируйте объект с компонентом Widget из `index.tsx`:

```tsx
import type { Plugin } from '@terminal/plugin'

export default {
  Widget: ({ instance }) => <p>Привет с рабочего стола {instance.desktop_id}!</p>,
} satisfies Plugin
```

Перезапустите backend и Vite, обновите страницу и выберите **+ Виджет → Приветствие**. Для проверки сборки выполните `npm run build` из `frontend/`. Файлы CSS и другие ресурсы можно импортировать по относительному пути из папки плагина. Используйте уникальный префикс для стилей. React и React DOM предоставляет frontend.

## Дополнительные точки входа

| Возможность в manifest | Точка входа | Поведение ядра |
| --- | --- | --- |
| `details` | Экспортируемый объект содержит React-компонент `Details` | Кнопка «Подробнее» открывает компонент поверх рабочего стола. |
| `settings` | Тот же объект содержит React-компонент `Settings` | В настройках экземпляра отображается форма плагина. |
| `backend` | `backend.py` экспортирует `router` типа FastAPI APIRouter | Сервер монтирует маршруты с префиксом `/api/plugins/<id>`. |

Экземпляр содержит `id`, `plugin_id`, `desktop_id`, `slot`, `width`, `height`, `settings` и `appearance`. `slot` — номер верхней левой клетки с нуля, в порядке чтения. Состояние API возвращает число колонок `columns`, предел `max_rows` и серверное значение `rows` для каждого стола. При добавлении, переносе и изменении размера оболочка передаёт в JSON поле `rows` с числом рядов, доступных в текущем окне. Для клиентов без этого поля сервер использует высоту занятой раскладки, минимум шесть рядов. Размер по умолчанию — 4×2 квадратные клетки. Размещение и размер принадлежат оболочке. `PUT /api/widgets/{id}/size` принимает целые положительные `width` и `height`; изменение размера сохраняет верхнюю левую клетку. При пересечении или выходе за границу сервер возвращает HTTP 409.

В меню ⋯ → Настройки секции «Оформление», «Размер» и «Выравнивание содержимого» доступны для всех экземпляров. Выравнивание компактного блока задают `appearance.horizontalAlign` (`left`, `center`, `right`) и `appearance.verticalAlign` (`top`, `center`, `bottom`). Оболочка применяет эти значения. Карточки без них используют прежнее размещение. Метод `PUT /api/widgets/{id}/alignment` принимает оба поля и обновляет их в существующем объекте оформления. Цветовые схемы названия и карточки хранятся в `appearance.titlePalette` и `appearance.cardPalette`. Единая кнопка «Сохранить» применяет изменения через `PUT /api/widgets/{id}/configuration`. При наличии возможности `settings` кнопка отправляет HTML-форму плагина, а её обработчик передаёт функциональные настройки для общей записи. Для дополнительных действий внутри формы используйте кнопки с `type="button"`.

Форма Settings дополнительно получает `saveSettings(next)`. Передайте полный объект функциональных настроек экземпляра, дождитесь Promise и обработайте ошибку в форме. Успешное сохранение обновляет данные ядра. Типы доступны в [контракте TypeScript](../frontend/src/plugin.ts).

Рабочий пример всех трёх представлений находится в [developer-demo](../plugins/developer-demo/index.tsx). При изменении подписи форма передаёт `{ ...instance.settings, label }`. После ошибки она оставляет введённый текст доступным для повторного сохранения. Поле `appearance` хранится отдельно. Счётчик — локальное состояние компонента на время его отображения.

Меню ⋯ принадлежит оболочке. Действие «Удалить виджет» вызывает `DELETE /api/widgets/{id}`, в том числе для заглушек отсутствующих плагинов. При успешном удалении сервер возвращает ID экземпляра, при неизвестном ID — HTTP 404. Удаление освобождает `slot` и сохраняет позиции остальных экземпляров.

Минимальный `backend.py` для плагина greeting с возможностью `backend`:

```python
from fastapi import APIRouter

router = APIRouter()

@router.get("/message")
def message():
    return {"text": "Привет!"}
```

Компонент может выполнить `fetch('/api/plugins/greeting/message')`. Серверные плагины выполняются в процессе FastAPI и рассчитаны на доверенный локальный код. Секреты интеграций храните на сервере. Дополнительные зависимости при необходимости устанавливает разработчик в соответствующее окружение.

## Проверка жизненного цикла

1. Добавьте два экземпляра и переместите один. Обновите страницу и проверьте их позиции.
2. Остановите оба процесса и временно переместите папку плагина за пределы `plugins/`. После запуска на прежних местах появятся заглушки. Ядро также работает при пустом каталоге.
3. Верните папку и перезапустите процессы. Экземпляры с прежним идентификатором получат сохранённые настройки. Если manifest или Python-модуль не загружается, причину можно найти в журнале backend.


## Шаблоны конструктора

Каталог также читает определения из SQLite. У шаблона собственный ID вида `template:<uuid>`, общий компонент карточки и номер ревизии. Тот же `WidgetInstance` хранит его размещение и оформление. Оболочка использует пространство ID с двоеточием отдельно от имён папок плагинов v1.

`POST /api/templates` создаёт определение, а `PUT /api/templates/{id}` принимает правки с исходной ревизией. Запрос `POST /api/widgets/{id}/actions/{action_id}` использует сохранённое определение действия и проверяет ревизию экземпляра. Отправители указывают команду, получатели привязаны по ID элемента и пути внутри результата. Пример настройки и формат `run(context)` приведены в [руководстве конструктора](../README.md#визуальный-конструктор).
