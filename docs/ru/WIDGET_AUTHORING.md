# Как подготовить виджет для импорта в RaspberryPi-Home-IT-Terminal

**Результат работы автора — папка с одним файлом `template.json`.** Файл описывает общий шаблон для визуального конструктора. После импорта он появляется в каталоге. Пользователь отдельно добавляет экземпляры шаблона на рабочие столы. Клетки элементов внутри карточки сохраняются в общем шаблоне. Положение самой карточки на рабочем столе, её размер, оформление и текущие значения принадлежат экземпляру.

## Папка и ZIP

```text
hello-card/
└── template.json
```

Имя папки выбирает автор. Имя файла фиксировано, в нижнем регистре. Файл обязательный, дополнительных файлов в формате нет. Сохраните обычный текстовый JSON в UTF-8, без комментариев и завершающих запятых. Даже код действия Python хранится строкой внутри JSON.

Для ZIP выполните команду из каталога, **содержащего** папку виджета. Например, для первого примера команда создаст архив с записью `hello-card/template.json`:

```bash
python3 -m zipfile -c hello-card.zip hello-card/
```

Проверьте, что в архиве один обычный файл на глубине ровно одной папки. Запись самой папки допустима. Уберите служебные файлы, включая `.DS_Store`. Используйте относительные пути с разделителем `/`. Импортёр отклоняет абсолютные пути, компоненты `.` и `..`, префиксы дисков, обратные косые черты и символические ссылки. Поддерживаются ZIP без пароля, с методом **Deflate** или **Stored**. Лимит для загружаемого архива и отдельно для распакованного JSON — по 8 МиБ.

## Поля шаблона

Корень JSON — объект. Типы проверяются строго. Например, интервал в одну секунду записывается числом `1`, включённый переключатель — значением `true`.

| Поле | Тип и обязательность | Содержание |
|---|---|---|
| `id` | строка, обязательно | Уникальный ID шаблона по выражению `^template:[0-9a-f]{32}$`. После префикса идут 32 строчные шестнадцатеричные цифры без дефисов. |
| `name` | строка, обязательно | Название в каталоге и на карточке, 1–100 символов, хотя бы один непробельный символ. |
| `rows` | массив массивов объектов, обязательно | От 1 до 64 строк. Всего в шаблоне от 1 до 128 элементов. |
| `actions` | массив объектов, обязательно | До 64 действий. Для статической карточки укажите `[]`. |
| `description` | строка, необязательно | Описание для каталога, до 2000 символов. По умолчанию пустое. Импорт убирает пробелы по краям. |
| `defaultWidth`, `defaultHeight` | целые числа, необязательно | Начальный размер экземпляра в клетках рабочего стола. Ширина 1–12 (по умолчанию 4), высота 1–2732 (по умолчанию 2). Для размещения нужен свободный прямоугольник этого размера в видимой сетке. Изменение шаблона влияет на размер будущих экземпляров. |
| `revision` | целое число, необязательно | Служебная ревизия. При создании пакета поле можно опустить. Первый импорт присваивает ревизию `1`. Повторный импорт после удаления увеличивает последнюю сохранённую ревизию. |

Для **нового** шаблона сгенерируйте собственный ID, например командой `python3 -c 'import uuid; print("template:" + uuid.uuid4().hex)'`. Повторный импорт занятого ID отклоняется, даже при другом названии папки. Установленный шаблон редактируется в конструкторе.

### Строки, колонки и элементы

Для новой карточки поместите все элементы в один массив внутри `rows`. Каждый элемент получает `frame`, например `"frame": {"x": 2, "y": 1, "width": 8, "height": 3}`. Это прямоугольник в мелких клетках под заголовком карточки. Координаты верхнего левого угла — целые числа от нуля, ширина и высота — целые числа от единицы. На каждую клетку рабочего стола приходится пять делений по каждой оси. При размере 4×2 доступно 20×10 делений. Прямоугольники могут касаться краями, пересечение или выход за границу отклоняются. При изменении размера экземпляра пропорции размещения сохраняются.

Для текста, кнопки, поля ввода и подписей переключателя и слайдера можно задать `fontSize` в пунктах (целое число от 1 до 144, по умолчанию 12) и `fontFamily` (`system`, `serif`, `monospace`). Растягивание рамки меняет доступное место. Размер букв задаётся в свойствах, лишний текст обрезается границами элемента. Пустая подпись переключателя или слайдера освобождает место для самого контрола.

Старые пакеты поддерживают автоматические строки, `cell` с координатами в крупных клетках и `span` с шириной 1–12. Конструктор переводит такую раскладку в рамки при редактировании. В пакетах с `frame` задайте рамки всем элементам и опустите `cell` и `span`.

У каждого элемента обязательны три строки: `id`, `kind` и `label`. ID элемента соответствует `^[A-Za-z][A-Za-z0-9_-]{0,63}$` и уникален среди элементов **всех** строк шаблона. Поле `label` содержит подпись длиной до 2000 символов. Связи используют ID, поэтому подпись можно менять.

| Значение `kind` | Поведение и дополнительные поля |
|---|---|
| `text` | Показывает `label` до первого результата. Без привязанного действия текст остаётся статическим. |
| `button` | Показывает `label`. При нажатии отправляет необязательную строку `command`. |
| `switch` | Переключатель с подписью. Начальное значение `checked` имеет тип boolean, по умолчанию `false`. При изменении может отправить `command`. |
| `slider` | Слайдер с подписью. Числовые поля `minimum`, `maximum`, `step`, `initial` по умолчанию равны 0, 100, 1 и 0 соответственно. При изменении может отправить `command`. |
| `indicator` | Цветной кружок. Подпись используется в подсказке и доступном названии. Начальный `color` — одна из строк `green`, `yellow`, `red`, по умолчанию `green`. |
| `input` | Однострочное поле. `inputMode` принимает `text` (по умолчанию), `number`, `ipv4`, `date` или `time`. `placeholder` задаёт подсказку до 200 символов. Пустая подсказка использует стандартный текст для формата. `resetCommand` задаёт необязательную команду очистки до 100 символов. |

Числа слайдера должны быть конечными, `minimum < maximum`, `step > 0`. Начальное значение должно лежать в диапазоне включительно и попадать на шаг от минимума. Например, при диапазоне от −1 до 1 и шаге 0.25 значение 0.5 допустимо. У всех отправителей `command` по умолчанию пустая строка, максимум 100 символов.

## Действия и назначение результата

Поле ввода хранит строку до 2000 символов отдельно для каждой карточки. В формате `number` допустимы цифры и одна точка, диапазон не проверяется. Дата передаётся строкой `YYYY-MM-DD`, время — строкой `HH:MM` в 24-часовом формате. Режим IPv4 показывает четыре части с точками и принимает числа от 0 до 255 в каждой. Незавершённый адрес передаётся как введённая строка. Действие Python читает значение по ID через `context["values"]`. Если `resetCommand` совпадает с командой отправителя в той же карточке, через 500 мс поле очищается и снова показывает подсказку. Действия по этой команде получают значения на момент отправки. Если пользователь изменил поле за это время, новая запись сохраняется.

Каждая запись в `actions` содержит обязательные поля:

| Поле | Тип и значения |
|---|---|
| `id` | Строка по тем же правилам, что ID элемента. Уникальна среди действий шаблона. |
| `name` | Название действия для редактора, строка длиной 1–100 символов. |
| `kind` | Строка `time`, `reach`, `http` или `python`. |
| `trigger` | Строка `command` или `timer`. |
| `targets` | Массив до 128 назначений результата. Для действия Python с запуском по команде допустим пустой массив. Остальным для запуска нужен хотя бы один получатель. |

### Режимы обновления

**Без обновления.** Оставьте элемент вне всех списков `targets`. Текст показывает `label`, индикатор — начальный `color`. В JSON этот режим задаётся отсутствием связи.

**По команде.** Задайте действию `"trigger": "command"` и непустую строку `command` до 100 символов. Отправьте эту строку из Python через `emit` или укажите её с учётом регистра в поле `command` кнопки, переключателя или слайдера этого шаблона. Кнопка отправляет команду при нажатии, переключатель и слайдер — при изменении значения. В текущем экземпляре запускаются все действия с этой командой, у которых есть получатели, а также действия Python без получателей. Сервер сохраняет результат в SQLite для этого экземпляра. Для двух независимых пар используйте разные команды и разные ID действий.

**По таймеру.** Укажите `"trigger": "timer"` и при необходимости `interval` — целое число секунд от 1 до 86400, по умолчанию 1. На активном рабочем столе действие запускается сразу, затем периодически. При смене стола, скрытии вкладки браузера или открытии конструктора таймер приостанавливается. Пока предыдущий запуск этого действия в экземпляре выполняется, следующий такт пропускается. Результат таймера хранится в памяти. Пример действия для текста с ID `clockText`:

```json
{"id":"tick","name":"Обновить часы","kind":"time","trigger":"timer","interval":1,"targets":[{"element":"clockText"}]}
```

**Получатели.** В каждом объекте `targets` обязательна строка `element` с ID существующего `text` или `indicator`. Необязательная строка `field` до 256 символов выбирает часть результата. При отсутствии `field` или значении `""` берётся весь результат. Точка разделяет ключи объекта, десятичный индекс выбирает элемент массива, например `sensors.0.value`. Текстовый получатель показывает пару `{"text": "98", "color": "red"}` как красное число 98. Для такого вывода верните объект ровно с двумя ключами: `text` (строка или число) и `color` (`green`, `yellow` или `red`). Чтобы вывести только число обычным цветом, задайте `field` равным `text`. В остальных случаях строки отображаются как есть, другие JSON-значения сериализуются в текст. Для индикатора результат должен быть точно `"green"`, `"yellow"` или `"red"`.

Одно действие может заполнить несколько получателей. Каждый получатель может быть указан только один раз во всём шаблоне. В конструкторе выбор **По команде** или **По таймеру** для элемента без связи создаёт отдельное действие. Общую связь можно задать через **Действие обновления**. Кнопка **Создать отдельное действие** копирует общую настройку для выбранного получателя. Для копии с запуском по команде укажите новое имя команды также у соответствующего отправителя.

### Что возвращает каждый вид действия

| `kind` | Входные данные | Результат |
|---|---|---|
| `time` | Дополнительные поля не нужны. | Строка с локальным временем сервера в формате `HH:MM:SS`. Назначьте её тексту целиком. |
| `reach` | `host` — имя хоста или IP без схемы URL, до 253 символов. При отсутствии `port` или значении `null` выполняется ICMP-проверка (в Debian нужен `iputils-ping`). Целый `port` от 1 до 65535 выбирает TCP-проверку. | Объект с полями `available` (boolean), `text` («Доступен» или «Недоступен») и `color` (`green` или `red`). |
| `http` | `url` — HTTP(S)-адрес с именем хоста. Сервер выполняет GET и читает JSON, до 1 МиБ. Необязательный строковый `path`, например `cpu.temperature`, выбирает часть ответа. | Выбранное значение, либо весь JSON при пустом `path`. Поле получателя `field` применяется **после** `path`. |
| `python` | `code` — строка до 32768 символов с определением функции `run(context)`. Внутри JSON перенос строки записывается как `\n`. | Значение, возвращённое через `return`, должно сериализоваться в JSON. Удобно вернуть словарь и назначить его поля разным получателям. |

Для Python в `context["values"]` доступны значения элементов своего экземпляра по ID, включая boolean переключателя, число слайдера и строку поля ввода. Также доступны `context["instance_id"]`, `context["template_id"]` и `context["action_id"]`. Для вычислений уже загружены `math`, `datetime`, `statistics`, `json`, `re`. Функция выполняется в отдельном ограниченном процессе Debian с таймаутом 4 секунды. Используйте готовые действия для сетевых запросов. Вывод `print()` служит диагностикой в карточке.

Из `run(context)` можно отправить команду другого действия в том же экземпляре. Например, кнопка отправляет `refresh`, а обработчик выбирает следующий шаг по переключателю с ID `enabledSwitch`.

```python
def run(context):
    if context["values"]["enabledSwitch"]:
        emit("read_sensor")
    else:
        emit("show_idle")
```

Создайте два действия с запуском по командам `read_sensor` и `show_idle`. Их имена должны совпадать с аргументом `emit` с учётом регистра. Для развилки укажите `"targets": []`. Можно одновременно вызвать `emit` и вернуть результат через `return`. После успешной обработки результата команды исполняются по порядку вызовов, включая вложенные шаги. Следующий шаг видит обновлённые выходы и значения ввода на момент запуска цепочки. Команда также может запустить сброс поля. Неизвестная команда, ошибка шага, цикл или превышение 64 запусков останавливают цепочку с сообщением в карточке.

При импорте сервер проверяет структуру, ссылки и синтаксис Python. Действия запускаются при работе экземпляра. Поэтому для проверки результата нужен размещённый виджет: ошибки выполнения и отсутствующие поля результата отображаются в карточке.

## Пример 1. Карточка с постоянным текстом

Создайте файл **`hello-card/template.json`** со следующим полным содержимым:

```json

  "name": "Приветствие",
  "rows": [
    [{"id": "greeting", "kind": "text", "label": "Добро пожаловать домой!", "frame": {"x": 1, "y": 1, "width": 18, "height": 5}}]
  ],
  "actions": []
}
```

## Пример 2. Проверка связи кнопки с действием

Создайте файл **`command-check/template.json`**. Пример проверяет локальную цепочку обновления карточки и работает без внешнего сервиса.

```json
{
  "id": "template:b90cd6aa039f49459af72cc39466ece2",
  "name": "Проверка действия",
  "description": "По нажатию кнопки обновляет сообщение и цвет индикатора.",
  "rows": [
    [{"id": "checkButton", "kind": "button", "label": "Проверить", "command": "refresh", "frame": {"x": 0, "y": 0, "width": 9, "height": 4}}],
    [
      {"id": "statusText", "kind": "text", "label": "Ожидает проверки", "frame": {"x": 0, "y": 5, "width": 15, "height": 4}},
      {"id": "statusLight", "kind": "indicator", "label": "Результат проверки", "color": "yellow", "frame": {"x": 16, "y": 5, "width": 3, "height": 3}}
    ]
  ],
  "actions": [
    {
      "id": "check",
      "name": "Подтвердить выполнение",
      "kind": "python",
      "trigger": "command",
      "command": "refresh",
      "code": "def run(context):\n    return {'message': 'Проверка пройдена', 'color': 'green'}",
      "targets": [
        {"element": "statusText", "field": "message"},
        {"element": "statusLight", "field": "color"}
      ]
    }
  ]
}
```

На новом экземпляре видны «Ожидает проверки» и жёлтый кружок. Нажмите **Проверить**. Команда `refresh` вызовет действие `check` один раз. Поле `message` заменит текст на «Проверка пройдена», а поле `color` сделает кружок зелёным.

## Установка и добавление на стол

**Через интерфейс.** На рабочем столе откройте **Создать виджет → Загрузить шаблон**. Нажмите **Выбрать папку** и укажите, например, саму папку `hello-card`, либо **Выбрать ZIP** и укажите архив с этой папкой внутри. После сообщения об успешном импорте кнопка **Открыть в конструкторе** позволяет проверить и отредактировать шаблон.

**Вручную.** Точный путь от корня репозитория — `template-packages/<имя-папки>/template.json`. Для первого примера в рабочей копии проекта это `/home/user/Projects/RaspberryDashboard/template-packages/hello-card/template.json`. Скопируйте туда папку пакета. Перезапустите backend обычной командой из корня репозитория (при локальном запуске сначала остановите прежний процесс через Ctrl+C):

```bash
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

При запуске backend проверит папки и сохранит новые шаблоны в SQLite. Причина отказа выводится в журнал backend. Если ID уже установлен, сохранённая версия и правки из конструктора сохранятся.

**Размещение одинаково для обоих способов.** На нужном рабочем столе нажмите **+ Виджет** и выберите название шаблона в каталоге. Повторите для второго экземпляра. Открыть общий шаблон позже можно через **Создать виджет → Шаблон**.

**Удаление.** Выберите сохранённый шаблон в конструкторе, нажмите **Удалить шаблон** и подтвердите. Размещённые экземпляры покажут заглушку. При запуске backend пропускает пакеты с удалёнными ID. Чтобы снова подключить пакет, загрузите его через интерфейс с прежним ID.
